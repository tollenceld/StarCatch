# 轨道数据与持续追踪架构

本文档定义 StarCatch 如何在“轨道数据足够新鲜”、“手机端连续追踪”和
“稳定的任务资料”之间分离职责。它补充 `ARCHITECTURE.md` 的运行时边界，
发布命令仍以 `Scripts/README.md` 为准。

## 核心决策

StarCatch 不应从网络持续下载“当前坐标”。轨道目标每一帧的 ECI 位置、
观察者的方位和仰角都应由设备上的 SatelliteKit/SGP4 从已验证轨道元素传播。
这条路径快、可复现、不依赖网络延迟，也不会上传观察者坐标。

为了让这种本地追踪在 App 发布数周后仍然有用，轨道元素则需要周期更新。
目标形态是 **offline-first 混合架构**：

1. App 始终携带一份通过发布门禁的完整快照，首启和无网状态可直接工作。
2. 有网时只下载版本化的轨道元素快照，不下载每帧坐标，不上传位置。
3. 客户端只从 StarCatch 控制的缓存/CDN 取快照，不让大量设备直接请求 CelesTrak。
4. 任何更新失败都继续使用“上一份已验证快照”；损坏文件永远不能覆盖可用数据。

CelesTrak 的 GP/OMM 接口为轨道元素来源。其使用政策说明 GP 数据约每两小时
更新，要求每次更新只下载一次，并建议有大量用户的服务自行建立缓存代理。
因此直连 CelesTrak 只属于发布管线，不属于 iPhone 运行时。

参考：

- [CelesTrak GP/OMM 查询格式](https://celestrak.org/NORAD/documentation/gp-data-formats.php)
- [CelesTrak Usage Policy](https://celestrak.org/usage-policy.php)
- [CelesTrak Supplemental GP 数据](https://celestrak.org/NORAD/elements/supplemental/)

## 三层数据所有权

### 1. 轨道层：高频变化的机器数据

- 主键：NORAD Catalog ID。
- 内容：CCSDS OMM/GP 元素、元素历元、数据源和快照时间。
- 更新频率：发布前必须更新；建立一方分发层后可每 6–12 小时生成新快照。
- 保留策略：当前验证版、上一验证版和随包版三级回退。
- 不承担：本地化句子、任务故事、视觉策展身份。

### 2. 身份与分类层：稳定的产品数据

- 主键：NORAD Catalog ID；COSPAR ID 用于发射批次关联，不代替主键。
- 内容：StarCatch 稳定 ID、类别、任务类型、星座家族、策展状态。
- 来源：`Scripts/catalog-curated.json` 和可保守重建的名称/分组规则。
- 更新规则：轨道元素更新不应改变已有对象的产品身份。

### 3. 内容层：低频变化的人类可读资料

- 主键：逐星档案使用 NORAD ID，星座共享档案使用 `CatalogFamily`。
- 内容：任务背景、时间线、工程事实和结构化来源。
- 编辑源：`SatelliteKnowledge/`；运行时产物：`Resources/satellite_profiles.json`。
- 生命周期：系统可删除已离开活动目录的 `review_status: generated` 档案；
  人工档案永不自动删除，必须由维护者决定是否转入历史策展目录。

当前 `catalog.json` 为了安装包加载效率，会把前两层编译成同一份运行时资源；
这是发布格式，不代表两层共享一个编辑事实源。

## 快照更新事务

每一份候选快照必须在被 App 采用前完成：

1. 在临时位置下载并解析 OMM，禁止覆盖现用文件。
2. 验证 schema、来源、对象数量下限、唯一 NORAD/COSPAR 身份和数值有限性。
3. 验证快照时间不在未来，非历史对象的元素历元不早于生成时间 14 天。
4. 用 Vallado 00005 与深空 04632 向量回归保护 SGP4/SDP4 数值路径。
5. 同步身份与内容，编译 `satellite_profiles.json`。
6. 发布时要求快照年龄不超过 72 小时。
7. 全部验证成功后才原子替换可用版；失败则保留 last-known-good。

未来的运行时更新器还应支持 `ETag`/`If-None-Match`、至少两小时的服务端新鲜度窗口、
指数退避、校验和/或签名、下载大小上限和原子文件替换。在一方稳定 URL 与签名密钥
尚未确定前，App 内不引入无法完成信任闭环的临时下载地址。

## 持续追踪准确度预算

空中指向误差不是单一数字，需要分别表达：

- **轨道误差**：元素新鲜度、阻力和机动使 LEO 对象比 GEO 更敏感。
- **观察者误差**：低轨目标存在明显视差；定位超过五分钟或误差半径超过 10 km
  的新样本不得被采用，水平误差大于 2 km 必须降级显示。
- **姿态误差**：只有定位可用且磁场达到中/高校准质量时才声明真北。
- **时间误差**：传播统一使用 UTC/Julian Date，不以 UI 动画时钟替代观测时间。
- **呈现误差**：真实 SGP4 帧之间可做短时间连续预测，但异常停滞时必须有界停止，
  不能用无限外推伪装成持续真值。

观察会话期间每四分钟请求一次新的单次定位，间隔短于五分钟样本有效期；
进入后台或离开天空页后停止刷新。这可以防止长时观测一直使用启动时坐标，
同时避免持续打开 GPS。

## 实施阶段

- **当前已落地**：随包完整 OMM 快照、本地 SGP4、发布新鲜度门禁、稳定 NORAD
  身份、资料编译、自动档案清理和观察期间周期定位。
- **接入一方分发层后**：实现快照 manifest、签名验证、原子切换、回退和非阻塞状态呈现。
- **不纳入观测器承诺**：碰撞分析、测量级定轨、未公开遥测、光学可见性保证。
